# Handoff

Everything below is committed (see `git log`). Read `CLAUDE.md` (rules, testing, gotchas) and `ROADMAP.md` (scope and ticks) too.

## How the user wants this built (decided 15/10/2026)
- Build the whole roadmap without stopping; ask questions only when genuinely blocked.
- **Strict phase order**: Phase 0 leftovers, then all of Phase 1, then Phase 2, and so on.
- Native or heavy dependencies are fine if the licence is permissive (MIT, BSD, Apache, ISC). Check with `npm view <pkg> license`; never GPL/AGPL/LGPL.
- Local commits on `main` only; the user pushes.
- Features that need a human (real printer, native dialogs, scanners, certificates): build them, verify everything a test hook can reach, and add them to the hand-test checklist below.
- The user asked for a professional look with icons, like a ribbon editor. Keep new UI consistent with the design system below.

## Current state
- Phases 0, 1, 2 and 3 complete (see ROADMAP). Phase 3: page organisation, copy/replace/split, Layout tab (headers, footers, numbers, Bates, watermarks, backgrounds, crop, resize), and bookmark, page label and link editing are done.
- Edit text (Phase 4, Edit tab):
  - Design: PDFium identifies the text object under the pointer (`pdfiumRaw.readTextObjects`: bounds, text, font name and flags, size, colour, matrix; the worker message is `textObjects`). The k-th PDFium text object is the k-th non-empty text-showing operator (Tj, TJ, ' or ") of the page's content stream: checked on 1,776 objects across five real PDFs with `scripts/textobj-check.mts` and `scripts/origin-check.mts` (counts only, no text printed).
  - `content.ts`: content stream tokenizer and operation parser with source ranges (inline images handled), `removeOps`, and `showOrigins` (where each show operator starts, from q/Q/cm/BT/Tm/Td/TD/T*/TL/'/").
  - `textEdit.replaceText`: refuses if the page's count of text objects differs from the stream's, or if the operator's start differs from PDFium's matrix origin by more than 1 pt. Removes the operator when later text will not move (the next show starts from a fresh position), else wraps it in `3 Tr ... n Tr` (invisible, original text stays in the file; the user is told). ' and " keep their line move (T*, and Tw/Tc). Replacement is drawn with pdf-lib `drawText` at the object's origin, size, colour and rotation, in the standard font from `pickStandardFont` (family from name and flags, bold and italic from name, weight, flags). Characters the font cannot show are refused.
  - UI: `TextEditLayer.tsx` outlines runs, click to edit (Enter commits, Esc cancels). The layer only appears once the viewer's client has loaded the current bytes (`textEditReady`), because object numbers change after every edit.
  - Font match: `shared/fontMatch.ts` reduces PDF font names and Windows font display names to a family key plus bold/italic; `main/fonts.ts` lists installed fonts from the registry (`reg query` on HKLM and HKCU Fonts, ttf/otf only) and reads the one file asked for (IPC `font:find`). `textEdit.embeddable` refuses fonts whose OS/2 fsType is restricted (0x2) or that lack a glyph; then a standard font is used. Embedded with @pdf-lib/fontkit (MIT), subset. Only exact weight and slant matches count.
  - Paragraph reflow: `textBlocks.groupBlocks` joins runs on one baseline into lines (gap at most 1.2 x size, same font, size and colour) and lines into paragraph blocks (spacing 0.9 to 2.2 x size and consistent, same left edge, first line may be indented). `plausibleParagraph` keeps tables out: every line but the last is several words and at least 60 % of the longest line, at most 60 lines; two lines only when the second continues the first (no sentence end, lower-case start). Upright text on an unrotated page only. `textEdit.replaceBlock` removes all the block's operators (a removed operator is only safe if what follows it is repositioned or is itself safely removed; else it is made invisible) and draws the new text wrapped by `wrapText` with the PDF font's metrics, at the first line's baseline and the measured leading; a single run is never wrapped. In the overlay Enter commits and Shift+Enter inserts a line break. Visual checks showed grids of one-character cells and tables being merged by an earlier version, hence the guards. `scripts/block-check.mts` prints block counts only.
  - Not done: text inside form XObjects (not listed by PDFium at page level), text with horizontal scaling or character spacing is redrawn without them.
- Edit images (Phase 4, Edit tab > Edit image): same design as Edit text. `pdfiumRaw.readImageObjects` lists PDFium's image objects (display rect, matrix) and the display-to-page matrix; `content.imageDraws` finds the stream's image draws (`Do` of an Image XObject, or an inline `BI`) with the CTM in force; `imageEdit.ts` refuses unless the counts match and the CTM equals PDFium's matrix (0.5 pt), then wraps the draw in `q <cm> ... Q` (move/resize: M = ctm x change x ctm^-1, so the new transform is ctm x change), swaps in a new embedded PNG/JPEG fitted inside the old box, or removes the draw. `ImageEditLayer.tsx` is the overlay; display-space edits become page-space with F^-1 x change x F. Checked on 221 images in five real PDFs with `scripts/image-check.mts` (counts only). Not done: rotate, crop, images inside forms, replacing with formats other than PNG/JPEG.
- Forms (Phase 5): `forms.ts` reads fields with pdf-lib (`readForm`: type, value, options, flags, DA size and colour, widgets with display-space rect, on-values, /MK colours and caption; a radio's on-value is its /Opt text when the state name is an index) and writes them (`applyFormValues`: setText/check/select, appearances regenerated per field, 12 pt for automatic multiline, an installed Unicode font for text Helvetica cannot show; `save({ updateFieldAppearances: false })` because they were made already). Pages are rendered with `forms: false` (worker `renderFormFields`, tile renderer skips FFLDraw) when the document has fields, and `FormLayer.tsx` draws controls over them. DocView keeps `formFields` (read from `bytes`), `formValues` (edits only; reset after save and page edits), `highlightFields`; `applyEdits` is async and writes annotations then form values. IMPORTANT: callbacks whose dependency lists carry `annotsDirty` must also carry `formValues` and `zDirty` (a stale closure once saved only the first edited field). Thumbnails, presentation mode and the snapshot tool still draw fields from the file's saved values. `scripts/make-form-pdf.mts` makes the all-field-types fixture (pdf-lib bakes the computed auto font size into DA, so the script sets sizes explicitly).
- Security (Phase 6): `shared/pdfSecurity.ts` (pure: `Permissions`, `encryptArgs`, `parseEncryptionJson`, `restrictsEditing`, `describeRestrictions`) and `main/qpdf.ts` (`encryptionInfo`, `decryptPdf`, `encryptPdf`, `copyEncryption`; IPC `pdf:encryption-info`, `pdf:decrypt`, `pdf:encrypt`, `pdf:copy-encryption`). AES-256 (R6) by default, AES-128 optional. IMPORTANT: qpdf's printed output does not reach the `print` callback inside Electron's main process (it does in plain Node), so information is read from `--json=latest --json-key=encrypt` written to a file. DocView: on open, a file with /Encrypt near its start or end (`mightBeEncrypted`) is asked about; one that needs a password shows the password form, one that opens without (only restrictions) is decrypted at once (`unlock`). `protection` is none, `copy` (the original encrypted bytes and the password, re-applied on save with `--copy-encryption`, so owner and user passwords, permissions and key length are kept) or `new` (settings from the Security dialog, written with `encryptPdf`); `protectionDirty` makes a protection change count as an unsaved change. If the permissions forbid changes and the owner password was not given, `lockReason` is set: banner with "Enter the permissions password…", the Edit, Forms, Comment, Draw, Measure, Organise and Layout tabs are disabled (the ribbon body is a fieldset), Highlight and Note too, save is refused; the owner password (`unlockOwner`) lifts it. Print is disabled when printing is forbidden, and Copy when copying is. No recovery snapshots are written for a protected document (they would be plain copies). `SecurityDialog.tsx`: open password (with confirmation), permissions password with printing and the other permissions, AES level, Remove security. Not done: enforcing the copy restriction on Ctrl+C and the snapshot tool, certificate-based encryption.
- Form scripts (Phase 5): `acrobatJs.ts` is the Acrobat Forms JavaScript subset written in plain JS (the prelude); `formScripts.ts` runs one script per fresh QuickJS runtime (`quickjs-emscripten-core` and `@jitl/quickjs-singlefile-mjs-release-sync`, MIT, pinned; about 130 ms to load once) with `shouldInterruptAfterDeadline` (250 ms), a 32 MB memory limit and a 512 KB stack. The form state goes in as one JSON string (`__inputJson`) and the outcome comes back as one JSON string, so there are no handles to manage and a script cannot reach files, network, timers or the app (tested). Numbers a script sets are converted to text. `readForm` reads /AA (F, K, V, C) into `FormField.scripts` and the form's /CO into `calcOrder`; `formDesign.writeScripts` writes them and keeps /CO in step. `scriptPresets.ts` builds the standard calls from the dialog choices and parses them back (anything else is "custom"). Runtime in DocView: `displayed` (format scripts, debounced; a focused editable field shows what was entered, selected on focus; a locked field always shows the formatted value), `commitField` (on blur, Enter, or any non-text change: keystroke then validate, reverting to the last accepted value when rejected, then `applyCalculations`), `recalculate` (calc fields in /CO order, up to 5 passes), button JavaScript (`this.resetForm()`, `getField().value = ...`), and `applyFormValues(..., display)` writes the formatted text into the appearance while /V keeps the raw value. Calculated fields are read-only in the UI. The dialog's script section is in `FieldDialog.tsx`. Scripts reference fields by name, so renaming a field does not rewrite them. `scripts/make-calc-pdf.mts` makes the scripted fixture.
- Form detection (Phase 5): `formDetect.ts` is pure over `DetectPage` (painted paths from `content.pathDraws`, which now also reports shape rect/line/other, stroked, filled, fill colour and line width; PDFium glyph boxes via `glyphsOf`; existing widgets). Evidence: runs of 3+ underscores or 8+ dots; stroked horizontal rules (36 to 400 pt) and empty stroked boxes (white or no fill) that have a label to the left or a caption below or above; small stroked squares (6 to 18 pt) with a label within 14 pt to the right become check boxes. Page furniture without a label is left alone. Names come from the label (`nameFromLabel`, made unique by `nameSuggestions`); the label also becomes the tooltip. `detectInDocument` loads the file with pdf-lib and asks PDFium for each page's text. `DetectDialog.tsx` confirms (more than 12 rules or boxes on a page start unticked); `addFields` creates them in one edit. `scripts/detect-check.mts` prints suggestion counts for real PDFs: none on prose and spec sheets, many on tables and drawings (by design the user confirms). Not done: comb fields, radio detection, fields inside form XObjects, scanned pages.
- Form designer (Phase 5): `formDesign.ts` (pdf-lib): `addField` (every kind; radio buttons join a group of the same name; a signature field is a hand-written widget dictionary because pdf-lib cannot create one; the box is shrunk by the border width because pdf-lib grows widgets by it; on a rotated page the content turns via /MK /R but the Rect stays in page space), `updateField`, `deleteField` (drops dangling /Annots), `placeWidget`, `setTabOrder` (/Tabs R, C or S), `moveInTabOrder` (swaps two widgets in /Annots). `FieldDialog.tsx` is the properties dialog (create returns a spec, edit returns a patch). Fill mode sorts widgets by the page's /Tabs setting. Every design change is a page edit (undoable, reloads the document). Button actions: reset and web address work; submit and JavaScript show a notice for now. Names cannot contain a full stop (dotted names are read but not created).
- Form data (Phase 5): `formData.ts` exports and imports field values as XFDF (nested for dotted names, several `<value>` for list boxes), FDF (UTF-16BE hex strings, nested /Kids), CSV (header row of names, one value row, list choices joined with "; ", BOM added by main) and plain XML; it has its own small tolerant XML reader so it is testable in Node. `valuesFromImport` maps text to values by field type (checkbox on-value or Yes/true/1/on; radio option text or index; list split; max length; read-only, buttons and signatures skipped). `forms.flattenForm` flattens with pdf-lib and removes the dangling /Annots references pdf-lib leaves. - Edit shape (Phase 4, Edit tab): vector paths in the page content. `content.pathDraws` finds painted paths (the run of m/l/c/v/y/re/h/W operators ending in S/s/f/F/f*/B/B*/b/b*; paths ending in `n` only clip and are skipped) with the CTM and a point bbox; `pdfiumRaw.readPathObjects` lists PDFium's path objects; `pathEdit.transformPath` checks counts and that the centres agree within 3 pt, refuses paths that also clip, and wraps the run in `q <cm> ... Q` or removes it. `scripts/path-check.mts` (counts only): 65,000 paths in six real PDFs, counts equal on every page, 99.98 % agree on position (the rest would be refused). `ObjectEditLayer.tsx` serves both Edit image (a box per image) and Edit shape (hit test under the pointer, smallest box first, 3 pt slop). Stroke width scales with a resize. Not done: editing path colours or line widths, dashes, shading objects, shapes inside form XObjects.
- Arrange annotations (Edit tab): Shift or Ctrl click adds to the selection (`selectedAnnot` is the primary, `extraSel` the rest; `selectAnnot(id, additive)`); dragging one of several moves all; Delete removes all. `arrange.ts` (pure, tested): `alignAnnots`, `distributeAnnots`, `restack`. Stacking order is the annotation list order; `zDirty` makes the save pass every annotation to `writeAnnotations(..., stacked = true)`, which rebuilds each page's /Annots (unmanaged entries such as popups and widgets first, ours after in order). - Add image (Edit tab): `imageEdit.addImage` places a PNG/JPEG as page content, 96 dpi capped at 240 pt and 60 % of the page, centred on the click, upright on rotated pages. `pendingImage` holds the picked file until the click.
- Signatures (Phase 6): `sign.ts` (renderer, pdf-lib + pkijs). `prepareSignature` appends the signature as an INCREMENTAL UPDATE (original bytes kept exactly, so earlier signatures stay valid): changed page, catalogue and form objects, the new field/widget, the signature dictionary with a fixed 20,000-byte /Contents placeholder and a ByteRange patched in place (ten-digit placeholders), an optional appearance stream (rotation handled with a /Matrix), then a classic xref section or an xref stream to match the file's own, and a trailer with /Prev. `finish(cms)` pastes the CMS blob in. The CMS itself comes from `main/signing.ts`: a PowerShell script (written to a temp folder per call; passwords via the environment) using .NET `SignedCms` with SHA-256, signing time and the whole chain, so Windows store keys (smart cards, non-exportable) and .pfx files both work; `chainStatus` asks Windows' X509Chain whether the signer is trusted (revocation not checked). Time-stamps: `buildTimestampRequest` / `addTimestamp` (pkijs) with the HTTP post done in main (`sign:timestamp`, `net.fetch`); the token goes in as an unsigned attribute. `readSignatures` + `verifySignature` check the digest, the signature (pkijs; ECDSA and RSA), the byte range and the time-stamp (pkijs wants the stamped data, here the signature value, for a TSTInfo). `describeSignature` words the result. DocView re-reads signatures whenever `bytes` change (a file rewritten by pdf-lib keeps its signature dictionary but compresses it, so `hadSigs` keeps it listed, reported as changed), shows a banner and the Signatures panel, and asks before anything (applyPageEdit, or Save with pending edits) would invalidate a valid signature. Signing goes through `applyPageEdit(..., keepsSignatures = true)` so it can be undone; the signed bytes are saved exactly as they are (Save writes `bytes` untouched when nothing else is pending). Certify = /Perms /DocMDP with a /Reference (P 1, 2 or 3). Tests: `sign.test.ts` (real signing through PowerShell with a throwaway .pfx made by Python's cryptography; time-stamp test uses a public TSA and skips offline), `e2e/sign.spec.ts` (OpenSSL verifies the saved signature independently). Not done: signing encrypted files (the dialog says to remove security first), LTV, certificate encryption.

- Plugins (Phase 8): a plugin is a folder `userData/plugins/<id>/` with `plugin.json` and one .js file per action (`shared/plugins.ts`: `validateManifest`, `normaliseStep`, `normaliseResult`). Manifest: apiVersion 1, id, name, version, `permits` (some of watermark, headerFooter, properties, rotate, flatten, sanitise, optimise, pdfa: never security, plugin or ocr), and actions with a label, a script name (no folders) and string parameters. The script runs in QuickJS (`pluginSandbox.ts`: 2 s, 64 MB, no files, network, clock or app access; page text capped at 500,000 characters), defines `run(doc, params)` and returns `{ steps, message }` or `{ error }`; steps are cleaned (numbers clamped, colours checked, text cut) and anything the manifest does not permit is dropped and counted. A plugin action is also a batch step (`{ kind: 'plugin', plugin, action, params }`) so it works in saved actions and on the command line. `main/plugins.ts`: install from a folder (keeps only plugin.json and the scripts it names, sizes and names checked) or a zip (at most 60 files and 4 MB, unsafe paths refused), uninstall, list, and the catalogue client (`{ plugins: [{ id, name, version, url, sha256, permits }] }`; https only, or http on this computer; the download must match its SHA-256 and its id before it is installed). `PluginsDialog.tsx` shows each plugin's permissions in words before anything runs. There is no hosted extension store and no default catalogue address: the user enters one. Plugins are not signed; the checksum only proves the download matches the catalogue.
- Embedded files and portfolios (Phase 8): `portfolio.ts`: `embedFiles` writes Filespec + EmbeddedFile streams (media type from the extension, size and date in /Params) into the catalogue's /Names /EmbeddedFiles, rebuilt as one flat tree sorted by name (name trees must be in order; a space sorts before a dot, so `notes (2).txt` comes before `notes.txt`), a taken name gets ` (2)`; `removeEmbedded` removes by index in that order (checked against the name) and calls `pruneUnreachable` so the data does not stay in the file; `createPortfolio` builds a cover page plus a `/Collection` (details view, Name, Size, Modified, Description columns); `isPortfolio` makes a portfolio open on the Attachments pane with a notice. - Compare (Phase 8): `compareDocs.ts` (pure): `tokenise` words per page, `diffTokens` (Myers O(ND) after trimming the shared start and end; gives up past 6000 edits and reports the rest as a deletion block plus an addition block), `groupChanges` (each run of differing words with six words of context and the pages on each side), `visualDiff` (pixels differing by more than 48 summed over RGB; red where only the first is dark, blue where only the second is, grey where equal) and `padTo` (white padding to a common size). `CompareDocsDialog.tsx` (Organise > Compare) picks the other file, loads it into a private PdfClient (disposed on close), and shows the text changes and a per-page overlay drawn on a canvas at 1.25x, with a 'check every page' pass that lists pages that differ. - Batch and command line (Phase 8): `batch.ts` defines `BatchStep` (watermark, headerFooter, optimise, ocr, sanitise, properties, flatten, pdfa, rotate, security) as plain JSON, `runSteps` (the same functions the interactive tools use), `checkSteps` (the security step must be last) and `runBatch` over a `BatchIO` (expand, read, write). `appEnv()` supplies OCR (a private PdfClient per file) and encryption/fonts through the main process. `main/batchIo.ts` expands files and folders to PDFs (max 5000), reads PDFs (max 1 GB), writes results as `<name><suffix>.pdf` into a folder or beside the source and NEVER overwrites (adds ` (2)`), and keeps saved actions in `userData/batch-actions.json`. `BatchDialog.tsx` (File > Batch). The command line (`main/cli.ts`, `parseCli`, `loadAction`): `OpenPDF --batch <name or .json> [--out dir] [--suffix s] [-r] [--report file] <files or folders>`, `--list-actions`, `--help`; exit 0 all processed, 1 some failed or none found, 2 bad arguments, 3 the hidden window crashed. A CLI run takes no single-instance lock and opens no main window: it opens a hidden window on the renderer with `?cli=1`, where `main.tsx` mounts `CliRunner` instead of the app; that asks the main process for the job (`cli:job`) and reports back (`cli:done`). Output goes to stdout when the process has one (it does when started with pipes, as the tests do); a packaged Windows GUI program started from a console window prints nothing, so `--report` is the reliable record. Passwords in a security step are saved in the action in plain text (the dialog says so).
- PDF/A output (Phase 7): `pdfa.ts` (`convertToPdfA`) works towards PDF/A-2b: XMP with pdfaid (built by `metadata.buildXmp`, kept equal to Info, dates added when missing), an sRGB output intent with a profile generated by `iccProfile.ts` (no third-party profile), installed fonts embedded in place of non-embedded simple fonts (standard 14 to Arial, Times New Roman, Courier New; whole TrueType files, widths for WinAnsi codes 32 to 255 from fontkit; fonts with Differences, CID fonts, OpenType/CFF and fonts with no installed match are reported), JavaScript and attachments removed (`sanitise`), annotation flags corrected, layer auto-switching removed, a file ID added. Reported as remaining: CMYK colour, annotations with no appearance, fonts it could not embed. It has NOT been run through a real validator (veraPDF needs Java, not installed): treat it as best effort and say so. `File > Convert to PDF/A` runs it as an undoable page edit and opens the Standards dialog with a list of what was fixed and what remains.
- OCR and scanning (Phase 7): `main/ocr.ts` runs tesseract.js 7 (Apache-2.0, WASM, LSTM only) in the main process (worker threads; one page at a time; the worker is stopped after 90 s idle and on quit). English data is copied from `@tesseract.js-data/eng` into `userData/tessdata`; other languages are downloaded from the jsDelivr copy of `@tesseract.js-data/<lang>/4.0.0_best_int` on first use (validated against a fixed list, gzip signature checked). The renderer renders each page at 200 to 400 dpi, sends the PNG, and `ocrLayer.ts` (`addTextLayer`) writes each word as invisible text (`3 Tr`) sized from the box height, squeezed with `Tz` to the box width, on the line's baseline, in page space through `frameFor` (so rotated pages work). Non-Latin languages use an installed font found by `findFont` (`fontsForLanguages`); words the font cannot show are skipped and counted. Pages that already have text are skipped unless asked. Packaging: tesseract.js starts worker threads from files inside its package, so the installer build must `asarUnpack` `node_modules/tesseract.js`, `tesseract.js-core` and `@tesseract.js-data` (not set up yet, see Phase 9). Scanning: `main/scan.ts` drives WIA from PowerShell (list devices; Windows' own scan dialog; or direct transfer from the glass or the feeder with colour mode and dpi; the feeder loop ends when the driver reports no paper). `OPENPDF_E2E_SCAN` (paths separated by `|`) replaces the scanner in tests. The scan becomes a new document at its physical size (pixels x 72 / dpi) and can be OCRed straight away. Device listing was checked on this PC (it found a network scanner through eSCL); an actual scan was not run.

- Redaction (Phase 6): `redact.ts`. Marks are kept in DocView (`redactMarks`, display space, drawn by `.redact-layer` in Viewer, tool `redact` reuses the crop drag gesture); nothing changes until Apply. `redactContent` (pure, unit-tested) picks PDFium text objects whose centre is in a mark or 10 % of whose area is, images the same way, and paths wholly inside; it removes the matching operators from the content stream using the same ordinal and origin checks as text and image editing (throws when the counts or positions disagree, so nothing is removed). A removed text operator that later text runs on from is replaced by `[-n] TJ` blank space so the rest stays put. `redactPages` then deletes annotations whose /Rect meets a mark, removes unused image resources, draws the black boxes with pdf-lib and calls `pruneUnreachable`: pdf-lib keeps cut-loose objects (old content stream, removed image) and writes them out, so the whole file is swept for objects not reachable from the trailer. The e2e spec scans every stream of the saved file for the removed text. Known limits: text is removed per text object (a line), not per character; an image partly under a mark is removed whole (no pixel blanking); content inside form XObjects is not reachable, so pages that draw them are reported ("could not be checked") but not cleaned; an inherited, shared resource dictionary keeps an unused image. Marks are not saved as /Redact annotations. `sanitise.ts` + `SanitiseDialog.tsx` (Redact tab > Hidden information): scans for and removes metadata (Info, XMP, PieceInfo), attached files, JavaScript and actions (names tree, OpenAction, /AA, field and widget actions), comments, bookmarks and thumbnails.
- Spell check: `main/spellMenu.ts` builds the text-box context menu (suggestions, Add to dictionary, edit commands); `Settings.spellcheck` (default on); `applySpelling` in `main/settings.ts` picks en-AU, en-GB or en-US if available, and sets the enabled flag last (setting a language can switch it back on). Not checked by hand: the visible underlines and suggestions depend on the Windows dictionaries (hand-test list).

## Known issues and limits
- An encrypted PDF is decrypted in memory when its password is given and encrypted again on save (see Security below). pdf-lib itself still cannot read or write encrypted files, so nothing in the editing code touches encrypted bytes.
- Applying a page edit writes pending annotation edits into the file first. Undoing the page edit brings them back as ordinary saved annotations.
- Deleting a page can leave a bookmark pointing at nothing.
- Rewriting bookmarks sends each one to the top of its page (any zoom or position in the original destination is dropped) and closes every bookmark that has children.
- An edited link keeps working from PDFium's copy until the file is saved (following a link uses PDFium's list).
- Underline and strikeout on sideways text are drawn horizontally.
- Thumbnails that have not rendered yet show a placeholder.
- Printed output is raster: text is not selectable in a print-to-PDF.
- Lint: some react-hooks rules are relaxed to warnings (see CLAUDE.md).
